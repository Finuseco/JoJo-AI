# Developer browser sign-in

The portal menu and legacy /dev/dashboard/studio enter /api/dev/jojo-ai, which redirects through https://ai.cashpay-all.com/api/auth/developer/start. AI creates a host-only HttpOnly state cookie and sends only its SHA-256 challenge to the portal. The portal reads its existing host-only developer session, verifies it, and issues an opaque random code for a signed grant (60-second expiry). The AI callback atomically consumes the code bound to that browser challenge, verifies HS256 signature, issuer, audience, Developer role and original session expiry, loads the developer identity, then sets its own HttpOnly session. No reusable session token appears in a redirect URL. Successful callbacks remove the code from the address bar.

This works for sessions created before domain-cookie sharing existed. A direct anonymous AI visit attempts silent recovery once; visitors without a portal session return to the sign-in screen without a redirect loop. Menu navigation from an authenticated portal reaches the projects dashboard. Empty accounts show first-project creation; existing owners and accepted collaborators see their authorized projects. Opening a project enters /workspace/:id.

Configuration: JoJo AI JOJO_AUTH_JWT_SECRET must equal portal DEV_PORTAL_JWT_SECRET (32+ characters). Both applications must access the same developer database. Run studio scripts/migrate.cjs or portal deploy/migrate-jojo-sso.cjs to create jojo_ai_sso_codes. Migrations are repeatable. Rebuild and restart both applications. Existing keys must not be regenerated to repair login.

The previous shared __Secure-cp_developer_sso cookie is still accepted for compatibility, but is not required by the handoff. If enabling DEV_PORTAL_SSO_COOKIE_DOMAIN, all subdomains must be trusted. Untrusted project previews must use a different registrable domain. A local studio session expires no later than the originating portal session; portal logout does not centrally revoke already-issued studio JWTs. Account switches through the portal menu issue a fresh studio session for the selected account.

Failures return a controlled sign-in screen. Check the shared database, migration and secrets. Logs never print grant tokens, authorization codes, signing secrets or personal account data. Windows has a separate browser cookie jar and must authenticate there.

Brand asset: public/brand/jojo-ai.png is the supplied owl image converted to PNG without regenerating the artwork. The UI uses object-contain at 44px in navigation, 112px during opening, plus the favicon. Reduced-motion disables the subtle arrival/loading animation. Application backgrounds remain solid.
